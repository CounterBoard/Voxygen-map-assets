# Контракт загрузчика карты Voxygen

Этот файл описывает формат данных между Worker `voxygen-map-assets` и React-клиентом основного репозитория `CounterBoard/Voxygen`.

## 1. Manifest

Запрос:

```http
GET /world-map/manifest.json
Cache-Control: no-store
```

Manifest — JSON-объект со следующими полями текущей схемы:

```json
{
  "schemaVersion": 1,
  "mapVersion": "unique-map-version",
  "source": {
    "type": "deepzoom",
    "width": 6001,
    "height": 6001,
    "tileSize": 512,
    "minLevel": 0,
    "maxLevel": 13,
    "format": "webp",
    "coordinateSystem": {
      "type": "minecraft-world-block-centers",
      "minX": -3008,
      "maxX": 3007,
      "minZ": -3008,
      "maxZ": 3007
    },
    "tileUrlTemplate": "/world-map/versions/unique-map-version/tiles/{level}/{x}_{y}.webp",
    "previewUrl": "/world-map/versions/unique-map-version/preview.webp"
  },
  "futureSources": {
    "urlGrid": {
      "type": "url-grid",
      "rows": 12,
      "columns": 12,
      "urls": []
    }
  },
  "generated": {
    "tileCount": 203,
    "tileSize": 512
  }
}
```

Значения размеров и количества тайлов в примере иллюстративны: клиент обязан читать их из полученного manifest, а не использовать пример как константу.

## 2. Deep Zoom — действующий формат

Поля `source`:

- `type`: строго `deepzoom`;
- `width`, `height`: реальные размеры исходного квадратного изображения;
- `tileSize`: размер стороны тайла в пикселях, сейчас 512;
- `minLevel`, `maxLevel`: включительные границы уровней;
- `format`: сейчас `webp`;
- `coordinateSystem`: фиксированная геометрия Minecraft-мира;
- `tileUrlTemplate`: шаблон URL с тремя placeholder;
- `previewUrl`: обзорное изображение.

Уровень `maxLevel` соответствует исходному разрешению. На каждом уровне ниже изображение уменьшается вдвое относительно предыдущего. Для уровня:

```
reduction = 2 ** (maxLevel - level)
levelWidth  = ceil(width  / reduction)
levelHeight = ceil(height / reduction)
columns = ceil(levelWidth / tileSize)
rows    = ceil(levelHeight / tileSize)
```

Имя тайла:

```
<level>/<x>_<y>.webp
```

Индексы `x` и `y` начинаются с нуля. Неполные правый и нижний тайлы сохраняют остаточный размер; padding до 512 пикселей не добавляется. Тайлы сохраняются в WebP без потерь.

## 3. Система координат мира

Координаты игрового мира не вычисляются из размеров изображения. Используется одна фиксированная геометрия:

- X: от -3008 до 3007 включительно;
- Z: от -3008 до 3007 включительно;
- ширина и высота диапазона: 6016 блоков;
- система: `minecraft-world-block-centers`.

Координата блока преобразуется в процент по центру блока:

```
xPercent = ((x - minX + 0.5) / 6016) * 100
yPercent = ((z - minZ + 0.5) / 6016) * 100
```

Старые manifest без `coordinateSystem` принимаются ради совместимости. Если поле присутствует, его тип и четыре границы должны соответствовать поддерживаемой геометрии.

Генератор принимает только квадратный исходный растр, чтобы масштаб X и Z оставался одинаковым. Разрешение растра при этом может быть любым в пределах ограничений генератора.

## 4. Preview и порядок загрузки

Клиент:
1. получает manifest без кэширования;
2. проверяет `mapVersion`, `source.type`, размеры Deep Zoom и совместимость геометрии;
3. разрешает `previewUrl` относительно origin map-assets Worker, если URL не абсолютный;
4. загружает и декодирует preview;
5. показывает preview как нижний слой карты;
6. вычисляет тайлы, необходимые текущему viewport и масштабу;
7. размещает загруженные тайлы поверх preview.

Preview обеспечивает видимую карту до загрузки детализированных тайлов и остаётся подложкой, если отдельный тайл не загрузился.

## 5. Выбор тайлов клиентом

Для Deep Zoom клиент:
- учитывает ширину/высоту viewport;
- учитывает текущий масштаб карты;
- учитывает `devicePixelRatio`, ограниченный диапазоном 1–3;
- выбирает уровень детализации по целевому числу пикселей;
- ограничивает уровень значениями `minLevel` и `maxLevel`;
- вычисляет прямоугольник видимой области в нормализованных координатах;
- добавляет запас по одному тайлу вокруг вычисленного прямоугольника;
- подставляет `level`, `x`, `y` в `tileUrlTemplate`;
- разрешает относительный URL относительно `assetBase`.

Список отображаемых тайлов обновляется с debounce около 110 мс после изменения viewport/масштаба. Pointer-жесты обновляют CSS transform через requestAnimationFrame, чтобы не перерисовывать React-дерево на каждом движении. Состояние viewport синхронизируется с родителем после жеста и с короткой задержкой во время движения.

Удаление тайла из React-списка прекращает его отображение. Отдельный AbortController для каждого уже начатого запроса `img` не используется.

## 6. Кэширование

`public/_headers` задаёт:

- `/world-map/versions/*`: `Cache-Control: public, max-age=31536000, immutable`;
- `/world-map/manifest.json`: `Cache-Control: no-store`.

Каждый URL preview и тайла включает `mapVersion`; опубликованные ресурсы версии считаются неизменяемыми. При смене manifest клиент начинает запрашивать URL новой версии. Старые browser cache entries не удаляются вручную.

## 7. Будущий формат url-grid

Резервная структура:

- `source.type = "url-grid"`;
- `source.rows = 12`;
- `source.columns = 12`;
- `source.urls` — массив из 144 URL, row-major: слева направо, сверху вниз;
- URL могут быть абсолютными или относительными к origin manifest;
- `source.previewUrl` — preview, показываемое до загрузки фрагментов.

Клиент содержит отдельную ветку выбора ячеек сетки по viewport. Однако текущий `tools/build_map.py` генерирует только Deep Zoom. В текущем manifest `futureSources.urlGrid.urls` пуст; url-grid не является активным форматом публикации.

## 8. Ошибки и совместимость

- HTTP 404 manifest: клиент может перейти к legacy `GET/HEAD /api/map` основного Worker.
- Любой иной HTTP-статус manifest: ошибка загрузки; legacy fallback не выполняется.
- Некорректный JSON, неподдерживаемый `source.type`, отсутствующий `mapVersion`, некорректные размеры Deep Zoom или несовместимая геометрия: manifest считается ошибочным.
- Отсутствующий или недоступный preview: карта не считается загруженной.
- Ошибка отдельного тайла не блокирует preview и остальные тайлы; отдельная UI-индикация ошибки тайла не предусмотрена.

## 9. Версия и готовность публикации

После загрузки исходника основной Worker возвращает `mapVersion` и статус `processing: "queued"`. Клиент опрашивает manifest до 25 минут. Публикация считается готовой для этого запроса, если:

- `manifest.mapVersion` совпадает с ожидаемой версией;
- тип источника поддерживается;
- координатная система совместима;
- preview успешно загружается и декодируется.

Успешный dispatch GitHub Actions не равнозначен завершённой публикации. Завершённость подтверждается появлением manifest ожидаемой версии и доступным preview.
